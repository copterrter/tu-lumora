# Phase 2 — สเปกและข้อตกลง (ระบบบูธ)

## ขอบเขตการใช้: ตอน Normal เท่านั้น

**แผนหน้านี้ (หน้า /booth + โค้ดส่วนลดจากบูธ) มีเพื่อใช้เฉพาะช่วง Normal ตาม logic ใน `lib/pricing.ts` เท่านั้น**

- **Normal** = หลัง Flash 1 จบ ถึง ก่อน Flash 2 เริ่ม (ตามขอบวันที่ใน code ตอนนี้คือ **15–18 มี.ค. 2026**)
- หน้ารวมถึงโค้ดที่ Gen จากบูธ ใช้ได้เฉพาะเมื่อระบบอยู่ phase **Normal** — พอเข้า **Flash 2** หรือ **Closed** โค้ดถือว่า **expired ใช้ไม่ได้**

## Logic Phase ตาม code (lib/pricing.ts)

| Phase (ใน code) | ช่วงเวลา (ตัวอย่างจาก code) | ราคา | ระบบบูธ / โค้ด |
|-----------------|------------------------------|------|-----------------|
| **Flash 1** | ถึง 14 มี.ค. 2026 23:59 | โปรคู่ 590 | ยังไม่เปิดบูธ |
| **Normal** | 15 มี.ค. – 18 มี.ค. 2026 | 329 ต่อตัว | **เปิดบูธ + โค้ดใช้ได้แค่ช่วงนี้** |
| **Flash 2** | 19 มี.ค. – 20 มี.ค. 2026 | 299 ต่อตัว | โค้ดจากบูธ **expired ใช้ไม่ได้** |
| **Closed** | หลัง 20 มี.ค. 2026 | ปิดรับออเดอร์ | โค้ดใช้ไม่ได้ |

สรุป: โค้ดที่ Gen จากบูธจะ **expire เมื่อเลย Normal** (เข้า Flash 2 หรือ Closed) ระบบต้องเช็ค `getCurrentPhase()` — ถ้าไม่ใช่ **normal** แล้ว ให้ถือว่าโค้ดใช้ไม่ได้

---

## ราคาตอน Normal (ช่วงบูธ)
- ช่วง Normal ขาย **329 บาทต่อตัวทุกตัว**
- ยอดรวม = จำนวนชิ้น × 329

## ระบบบูธ + โค้ดส่วนลด (ใช้ได้ตอน Normal เท่านั้น)
- หน้า `/booth` (QR → สุ่มรางวัล, แชร์ IG ถ้าได้ 0%, Copy/Save โค้ด)
- ตาราง `promo_codes` + API สุ่ม/Gen โค้ด (Tier **10% / 15% / 50%** เท่านั้น — ไม่มี 5%)
- ช่อง Promo Code ที่ Checkout + Apply + คำนวณส่วนลด
- **เงื่อนไขใช้โค้ด:** ส่วนลดจากบูธใช้ได้**เมื่อซื้อแค่ 1 ตัวเท่านั้น** (ถ้าซื้อ 2 ตัวขึ้นไป ใช้โค้ดนี้ไม่ได้)
- **หมดอายุ:** โค้ดจากบูธใช้ได้**แค่ตอน Normal** — พอเข้า Flash 2 หรือ Closed ถือว่า **expired ใช้ไม่ได้**
- **ส่วนลดจากโค้ด** = 329 × (X% ตาม tier) — ยอดสุทธิ = 329 − ส่วนลด
- ไม่ต้องมี logic “ใช้ร่วมกับโปร 2 ตัว 590” — เพราะช่วง Normal ไม่มีโปรนั้น

## สุ่ม 0% (Viral)
- ได้ 0% → ต้องแชร์ IG Story ถึงจะสุ่มใหม่ได้ (หน่วง 5 วินาที)
- **ไม่บังคับ** ให้รอบถัดไปห้ามออก 0% — รอบหลังแชร์ยังสุ่มได้ 0% ได้ตามปกติ (ทาง human ให้ user สุ่มจนไม่โดน 0% เอง)

## สรุปสิ่งที่ต้องทำ (Phase 2)

### 1. ฐานข้อมูล
- สร้างตาราง `promo_codes`: `id`, `code_name` (unique), `discount_percent`, `is_used`, `created_at` — ใช้ logic ว่า “ใช้ได้แค่เมื่อ `getCurrentPhase() === 'normal'`” (เลย Normal แล้วถือว่า expired)
- โค้ด Gen จากระบบบูธเท่านั้น (Prefix LUMO10 / LUMO15 / LUMO50 ตาม tier — ไม่มี LUMO05)

**รัน migration**

- **แบบ Supabase CLI:**  
  1. Link โปรเจกต์ครั้งเดียว: `npm run db:link` → ใส่ Project ref (Dashboard → Settings → General → Reference ID) และ Database password  
  2. Push: `npm run db:push`  
  รายละเอียด: `supabase/README.md`
- **แบบ SQL Editor:**  
  Supabase Dashboard → SQL Editor → รันตามลำดับ:  
  1) `supabase/migrations/20260315000000_promo_codes.sql`  
  2) `supabase/migrations/20260315000001_orders_promo_code.sql`  
  3) `supabase/migrations/20260316000000_booth_atomic_quota_and_ratelimit.sql` (RPC โควต้า + ตาราง rate limit)

### 2. หน้า Booth (`/booth`)
- หน้า Mobile-first สำหรับสแกน QR ที่บูธ
- แสดงมาสคอตลูโม่ + ปุ่ม **สุ่มรางวัล** → Animation สปิน
- **ผลมีส่วนลด (10%, 15%, 50%):** Pop-up แสดงโค้ด + ปุ่ม Copy Code + Save to Camera Roll
- **ผล 0%:** ข้อความ “ลูโม่แอบกินส่วนลด…” + บังคับแชร์ IG Story → หน่วง 5 วินาที → ปลดล็อกสุ่มใหม่ (รอบถัดไปยังสุ่มได้ 0% ได้)
- ปุ่ม **Shop Now** → `/product` และ **Back to Home** → `/`
- ข้อความเตือน: “อย่าลืม! นำโค้ดไปกรอกในช่อง Promo Code ที่หน้าชำระเงินหล่ะ”

### 3. API บูธ
- **POST /api/booth/spin**: สุ่มตามความน่าจะเป็น + โควต้า (50% สูงสุด 2, 15% สูงสุด 20, 10% สูงสุด 50, 0% ไม่จำกัด — ไม่มี tier 5%). **เรท:** 50% = 0.1%, 0% = 50%, 15% = 15%, 10% = 34.9% (ลดหลั่น). ถ้าออก 10/15/50 ให้ Gen โค้ดและบันทึกลง `promo_codes`

### 4. หน้า Checkout อัปเดต
- **ตอน Normal เท่านั้น:** แสดงช่อง **Promo Code / โค้ดส่วนลดจากบูธ** + ปุ่ม **Apply**
- **เมื่อถึง Flash 2 (หรือ Closed):** **เอาช่องใส่โค้ดออกเลย** — ไม่แสดงช่อง Promo Code และปุ่ม Apply (ไม่ใช่แค่ปิดใช้)
- เช็คโค้ด: มีใน DB และ `is_used = false` และ **จำนวนชิ้นในออเดอร์ = 1** และ **ระบบอยู่ phase Normal** (`getCurrentPhase() === 'normal'`) ถึงจะใช้ได้
- Apply สำเร็จ: แสดง “ใช้โค้ดสำเร็จ ลด X%”, ยอดส่วนลดสีแดง, อัปเดตยอดสุทธิ (329 − ส่วนลด)
- โค้ดผิด/ใช้แล้ว/ซื้อมากกว่า 1 ตัว/หมดอายุ (ไม่ใช่ Normal): แจ้ง Alert แดง
- เมื่อกด Confirm & Pay และบันทึกออเดอร์สำเร็จ → อัปเดต `promo_codes.is_used = true`
- **เมลใบเสร็จ:** เมื่อออเดอร์ใช้โค้ดส่วนลด ต้องแจ้งในเมลด้วย — เรียก `sendOrderReceipt` โดยส่ง **`discountLabel: 'ส่วนลดจากโค้ด'`** (แถวส่วนลดในเมลจะแสดงข้อความนี้แทน "Squad Promo" รูปแบบเดิมเหมือนเดิม)

### 5. ราคาตอน Normal
- ช่วง Normal หน้า product / pricing ใช้ 329 บาทต่อตัวทุกตัว (ตาม logic เดิมใน `lib/pricing.ts` ไม่ต้องเปลี่ยน)

## ช่องโหว่ / ข้อควรระวัง (ช่วง Normal)

| ประเภท | ความเสี่ยง | แนวทางแก้ |
|--------|------------|-----------|
| **โควต้า 50%** | สองคนกดสุ่มพร้อมกัน อาจได้ 50% เกิน 2 สิทธิ์ | ตอน Gen โค้ดใน API ต้อง **เช็คโควต้าใน transaction** (หรือ lock) — นับโค้ดที่ยังไม่ใช้ของ tier นั้นก่อน insert แล้ว insert แค่เมื่อไม่เกินโควต้า |
| **สแปมสุ่ม** | ไม่มี login — คนเดียวกดสุ่มซ้ำเรื่อยๆ ได้ | **Rate limit** ต่อ IP หรือต่อ session (เช่น 1 ครั้งต่อ 30 วินาที หรือจำกัดครั้งต่ออุปกรณ์ต่อวัน) เพื่อไม่ให้ดึงโค้ด 50% หมด |
| **Apply แล้วเพิ่มของ** | ลูกค้า Apply โค้ด (1 ตัว) แล้วไปเพิ่มเป็น 2 ตัวในตะกร้า | เมื่อ **จำนวนชิ้น > 1** ให้ **ยกเลิกโค้ดที่ Apply ไว้** และคำนวณยอดใหม่ (ไม่ให้ใช้โค้ดกับออเดอร์ 2 ตัว) |
| **เปิดแท็บค้างข้าม phase** | ลูกค้า Apply โค้ดตอน Normal แล้วเปิดแท็บค้างถึง Flash 2 | ตอนโหลด Checkout และก่อนส่งออเดอร์: ถ้า **phase !== 'normal'** ให้ **ไม่แสดงช่องโค้ด + ล้างโค้ดที่เคย Apply** และคำนวณยอดไม่มีส่วนลด |
| **ยืนยันส่วนลดฝั่ง server** | แก้ request ฝั่ง client ให้ส่งยอดลดเอง | ตอน **สร้างออเดอร์ (verify)** ต้อง **เช็คโค้ดและ phase อีกครั้งฝั่ง server** แล้วคำนวณยอดจากโค้ดใน DB — ไม่เชื่อยอดจาก frontend อย่างเดียว |
| **บันทึกออเดอร์ว่าใช้โค้ด** | ส่งเมลไม่รู้ว่าเป็นส่วนลดจากโค้ดหรือโปร | ในตาราง `orders` ควรมีฟิลด์ **promo_code_used** (หรือเก็บ code_name ที่ใช้) เพื่อตอนส่งเมลส่ง **discountLabel: 'ส่วนลดจากโค้ด'** และ mark โค้ด is_used ถูกตัว |
| **หน้า /booth หลัง Normal** | เปิด /booth ตอน Flash 2 ได้ อาจสับสน | เมื่อ **phase !== 'normal'** หน้า /booth แสดง **"กิจกรรมสิ้นสุดแล้ว"** และ **ไม่ให้กดสุ่ม** (หรือ API spin ตอบ error ถ้าไม่ใช่ Normal) |

---
*อัปเดต: แผนหน้านี้มีเพื่อใช้ตอน Normal เท่านั้น — โค้ดจากบูธใช้ได้แค่ 1 ตัว และใช้ได้แค่เมื่อ phase = normal, เลย Normal แล้ว expired*
